# Review — v0.20.0 Admin event filters

Date: 2026-08-06  
Scope: Filter Admin Events list by status, date range, venue/place, text search, and all-day

## Architecture

- `EventRepository.listAll` accepts `AdminEventListOptions` and applies Prisma `where` (status, `startAt` range, `allDay`, title/slug/summary `q`, venue name/city/address), ordered by `startAt`, with venue + categories included.
- Admin API validates status / `allDay` / dates; calendar `dateTo` (YYYY-MM-DD) is inclusive through end of UTC day.
- Admin UI builds query from applied filters (draft → apply) so typing does not refetch on every keystroke.

## Ops / UX

- Filter panel above bulk actions; empty state distinguishes “no events” vs “no matches”.
- Event rows show venue name/city when present.
- Status filter covers the v0.19.0 follow-up (list only `pending_moderation`).

## Follow-ups

- Optional pagination / offset when filtered sets exceed `limit` (200 max in repository).
- Optional category/region filters when moderation workflows need taxonomy slices.
