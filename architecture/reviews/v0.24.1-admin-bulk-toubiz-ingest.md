# Review — v0.24.1 Admin bulk events & Toubiz ingest

Date: 2026-08-20  
Scope: Admin Events bulk mutations vs API rate limit; Toubiz EMS category/venue/description fidelity

## Architecture

- Collection endpoints `PATCH /api/v1/admin/events/bulk-status` and `POST /api/v1/admin/events/bulk-delete` update/delete up to 200 events in one request (EventVersion + audit).
- Nest Throttler still protects public API and login; `/api/v1/admin/*` is skipped (JWT + RBAC remain).
- Toubiz plugin `1.1.0` paginates `eventDates` (address per occurrence) and hydrates `/api/v1/event/{id}` for description/category.
- `ExtractedEventFields.sourceCategories` plus `AiJobPayload.pluginEvent`: plugin fields coalesce over LLM gaps; taxonomy prefers EMS labels over festival guesses.
- Classification prompt **1.0.5**; curated catalog adds Tanzkurs, Vortrag, Ausstellung.

## Product

- Selecting many Admin Events to publish/delete no longer returns `429 ThrottlerException`.
- Rotkäppchenland-style Toubiz sources keep e.g. Tanzkurs, Glashaus street address, and the long description instead of empty text + Kirmes.

## Follow-ups

- Re-crawl existing Toubiz sources after deploy; `db:seed` upserts the new category rows on existing databases.
- Optional: raise Toubiz detail fetch concurrency if crawls approach the scheduler tick budget.
