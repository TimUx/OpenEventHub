# Review — v0.26.0 Lokalität vs Ort & Venue-Normalisierung

Date: 2026-08-20  
Scope: Admin Events labeling (Lokalität / Ort / Adresse); compound POI settlement extract; venue name/address normalize without new Prisma field

## Architecture

- Shared `venue-normalize.ts`: `streetLineFromAddress`, `buildingLocalityFromLabel` — Ort stays on `Venue.regionId`, building on `Venue.name`, street on `Venue.address`.
- AI `resolveVenue` + Admin Events PATCH apply normalize on persist; Toubiz `addressLine` emits street only; `repair-dev-regions` rewrites existing venues.
- Compound `*kirche` in `VENUE_OR_POI_TOKEN` so `Schlosskirche Ziegenhain` → settlement `Ziegenhain`.
- No schema change: building ≠ extra column (would duplicate `Venue.name`).

## Product

- Admin Events shows e.g. `Schlosskirche · Ziegenhain` with street under; dropdown **Ort (Region)** for `venueRegionId`.
- Operators are less likely to confuse venue building with hierarchy place.

## Follow-ups

- After local/DEV upgrade: `bash scripts/repair-dev-regions.sh` to shorten existing addresses/names.
- Optional later: geocoding query preference when address is street-only (region name already joined).
