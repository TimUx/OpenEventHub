# Review — v0.24.0 Geocoding worker, media & Admin events

Date: 2026-08-09  
Scope: Async Nominatim geocoding, region coordinates, crawl media, Admin Events/i18n

## Architecture

- Shared geocoding job payload + Nominatim client in `@openeventhub/shared`; enqueue from `ai-service` (post-ingest) and API (admin place / backfill).
- `worker` consumes BullMQ queue `geocoding` (concurrency 1, rate-limited); persists venue lat/lng and optional region coords; Compose/Stack attach worker to `edge` + `internal`.
- Prisma migration adds Region latitude/longitude; venues/media repositories extended for admin and public event detail.
- HTML plugin extracts og:image / JSON-LD images into Media rows during crawl processing.

## Product

- Operators can backfill missing coordinates and edit event place (Ort/Adresse), region, and category in Admin Events.
- Unmatched category inference falls back to curated **Sonstiges**.
- Public event detail shows crawl-derived images; Admin chrome strings use shared i18n labels.

## Follow-ups

- Optional Nominatim result cache table if queue volume grows.
- Broader media types (flyer OCR images already separate) and CDN/object-store rewrite for hotlink safety.
